# 03 · 서비스 정책

# BATON 서비스 정책 v2.0

기준일 . 최신 화면설계서와 기능명세서 v3.2에 맞춰 개정했다. PM이 직접 확정한 요구와 PM이 위임한 세부 운영값을 반영했다. 이 문서는 기존 정책서 v1.3의 충돌하는 내용을 대체한다.

## 1. 이번 기준

- 앱 내부 알림 포함. 외부 푸시·대타 공유 링크 제외.
- 매니저는 근무 추가·반복 등록·단건 삭제·최종 승인/거절, 크루원은 대타 요청·수락/거절·취소/철회.
- 근무 수정·양쪽 근무 변경 이력 UI·매니저 요청/후보 참여·AP-01·체험 우회·코드 재발급 UI 제외.
- 크루원 거절은 즉시 처리. 매니저 최종 승인·거절의 확인은 유지. 거절 사유 입력 없음.

## 3. 처리 기준

| 기준 ID | 항목 | 처리 기준 |
| --- | --- | --- |
| B01 | 소속·권한 | 모든 조회/변경에서 인증 사용자, 활성 매장 소속, 역할, 요청 관계를 서버에서 검증한다. 이름이 아닌 ID로 판정한다. |
| B02 | 다른 매장 접근 | URL이나 ID를 바꿔도 다른 매장의 시간표/요청에 접근하지 못한다. |
| B03 | 근무 저장 | 근무 저장 성공 시 공유 근무표에 반영하며 별도 게시/배정 수락 단계는 두지 않는다. |
| B04 | 반복 근무 | 반복 등록은 날짜별 독립 근무다. 한 날짜 삭제는 다른 날짜에 전파하지 않는다. 반복 기간은 달력상 1개월이다. 종료일은 시작일에 달력상 1개월을 더한 날짜 이하이며 시작일·종료일 모두 반복 대상에 포함한다. 다음 달에 같은 일자가 없으면 다음 달 말일을 상한으로 한다. 예: 2026-11-04 시작의 최종 종료일은 2026-12-04, 2027-01-31 시작은 2027-02-28이다. 30일 또는 31일 고정 일수로 계산하지 않는다. |
| B05 | 완전 동일 중복 | 매장·담당자·날짜·시작·종료가 모두 같은 근무는 새로 생성하지 않는다. 일부 시간 겹침 차단은 기존 범위에 포함되지 않는다. |
| B06 | 일괄 등록 | 미리보기는 쓰기 없음. 최종 저장은 전체 성공/전체 실패. 재시도에도 같은 등록 건이 중복되지 않아야 한다. |
| B07 | 요청 생성 조건 | 시작 전 본인 근무를 가진 크루원만 요청한다. 본인·매니저 제외 같은 매장 현재 소속 크루원을 1명 이상 지정하고 진행 요청은 근무당 하나다. |
| B08 | 요청 생성 | 요청 생성 성공 시 지정 상대의 앱 내부 받은 요청에 등록하고 새 요청 알림을 생성한다. 공유 URL·공유 팝업·푸시 작업은 생성하지 않는다. |
| B09 | 외부 공유 제외 | 대타 외부 공유·재공유·링크 복사는 MVP 제외한다. 매장 초대 코드 복사는 별도 유지한다. |
| B10 | 요청 상세 권한 | 앱 내부 요청 상세는 요청자·지정 대상·활성 소속 매니저에게만 허용한다. 외부 공유 링크 진입은 MVP 제외한다. |
| B11 | 첫 수락 | 동시 수락에도 후보는 한 명만 저장한다. 수락 후 매니저 승인 대기이며 근무 담당자는 아직 바뀌지 않는다. |
| B12 | 일부/전원 거절 | 크루원 거절하기는 확인 팝업 없이 즉시 처리한다. 일부 거절은 나머지 대상의 응답을 막지 않는다. 거절한 대상도 유효한 WAITING에서 다시 수락 가능하며 전원 거절이면 ALL\_DECLINED로 종료한다. |
| B13 | 요청 취소 | 요청자는 승인 전 진행 중 요청을 취소할 수 있다. 승인 완료 후 취소로 근무를 되돌리지 않는다. |
| B14 | 후보 철회 | 현재 후보만 승인 전 철회. 요청 전체 종료, 다른 대상에게 자동 재모집하지 않는다. |
| B15 | 만료 | 원래 근무 시작 시각 이상이면 응답 대기와 승인 대기를 모두 만료한다. 단말 시각이 아닌 서버 시각을 검사한다. |
| B16 | 승인 처리 | 소속 매니저가 후보·PENDING\_MANAGER·시작 전·원본 담당자 및 버전을 재확인한다. 최종 승인 확인에서 해당 근무 담당자·요청 상태·처리 기록·결과 알림을 함께 확정한다. 매니저 요청/후보 시나리오는 제외한다. |
| B17 | 원본 변경 | 근무 삭제 시 진행 요청도 CANCELLED\_SOURCE\_CHANGED로 종료하고 삭제 사유와 필요한 결과를 함께 기록한다. 근무 수정 기능에 의한 종료는 제외한다. |
| B18 | 매니저 거절 | 매니저의 최종 거절은 기존 확인 팝업 후 REJECTED로 종료하고 원래 담당자를 유지한다. 거절 사유 작성창·사유 필드·필수 검증은 제공하지 않는다. |
| B19 | 앱 내부 알림·승인 진입 | 앱 내부 알림은 필수이며 NT-01 단일 목록이다. 첫 수락 후 승인 요청, 처리 결과를 N01\~N08·이벤트 표에 따라 전송한다. 알림 화면 진입 읽음은 승인 처리와 무관하다. 푸시는 제외한다. 알림이 만료된 뒤에도 매니저 SH-02의 승인 대기 요청 보기에서 AP-02에 접근할 수 있어야 한다. |
| B20 | 재시도/동시성 | 이미 처리된 행동, 오래된 버전, 중복 제출은 중복 변경하지 않는다. 최신 상태를 반환하거나 재조회하도록 한다. |
| B21 | 이력 분리 | 근무 변경 이력 UI는 제외하지만 활성 계정의 요청 진행·처리 결과 기록은 유지한다. 알림의 7일 보관과 요청 기록을 구분한다. 계정 탈퇴 시 개인 관련 기록은 개인정보 정책에 따라 파기·익명 처리한다. |
| B22 | 시간/집계 | 매장 시간대 Asia/Seoul. 인원수는 중복 사람 제거, 근무 건수는 근무별 계산. API 요일 1=월\~7=일을 클라이언트와 일치시킨다. |

## 5. 요청 상태 전이

| 현재 상태 | 사건 | 결과·사유 | 담당자 |
| --- | --- | --- | --- |
| 없음 | 크루원 요청 생성 | WAITING | 원래 담당자 유지 |
| WAITING | 첫 수락 | PENDING\_MANAGER | 원래 담당자 유지 |
| WAITING | 일부 거절 | WAITING | 원래 담당자 유지 |
| WAITING | 전원 거절 | ALL\_DECLINED | 원래 담당자 유지 |
| WAITING / PENDING\_MANAGER | 요청자 취소 | CANCELLED | 원래 담당자 유지 |
| PENDING\_MANAGER | 후보 철회 | WITHDRAWN | 원래 담당자 유지 |
| PENDING\_MANAGER | 매니저 승인 | APPROVED | 해당 근무만 후보로 변경 |
| PENDING\_MANAGER | 매니저 거절 | REJECTED | 원래 담당자 유지 |
| 진행 중 | 시작 시각 도달 | EXPIRED | 원래 담당자 유지 |
| 진행 중 | 근무 삭제 | CANCELLED\_SOURCE\_CHANGED | 근무 삭제 |
| 진행 중 | 요청자 소속 해제 | CANCELLED / REQUESTER\_LEFT | 별도 담당자 변경 없음 |
| PENDING\_MANAGER | 후보 소속 해제 | WITHDRAWN / CANDIDATE\_LEFT | 원래 담당자 유지 |
| WAITING | 소속 해제로 응답 가능 대상 0명 | CANCELLED / NO\_ACTIVE\_TARGET | 원래 담당자 유지 |
| 종료 | 중복 처리·늦은 응답 | 추가 변경 없음 | 최신 담당자 유지 |

상태 코드의 표현은 기존 API 계약과 통일한다. CANCELLED\_SOURCE\_CHANGED는 이번 범위에서 근무 삭제에만 적용한다. 소속 해제 사유 코드는 화면을 새로 늘리지 않고 기존 종료 결과 레이아웃에 표시한다.

| N07 | 표시점 | 매니저·크루원 모두 최근 7일 내 미읽음 수신 알림 존재 여부로 점을 표시한다. 목록 진입 읽음 성공 시 사라지고 이후 새 알림이 오면 다시 표시한다. 미처리 승인 건수로 점을 유지하지 않는다. | NTF-01 / NTF-05 |
| N08 | 데이터 구분 | 알림은 7일 확인 목록, 요청 기록은 대타 진행 상태다. 알림 만료·읽음으로 요청이나 승인 대기를 삭제하지 않는다. 근무 변경 이력 화면은 제공하지 않는다. | NTF-01\~05 / SUB-05 |

“알림 화면 진입 시 읽음”은 자동 동작이다. 사용자가 누르는 전체 읽음 버튼은 없다. 알림 조회와 읽음 저장이 실패하면 확인 완료로 표시하지 않는다. 생성 시각은 서버 시각을 쓰고 실제 표시 시간대는 Asia/Seoul이다.

## 8. 계정·소속·개인정보

| 항목 | 적용 기준 |
| --- | --- |
| 계정 탈퇴 | 매장 나가기·탈퇴 확정 직전에 아직 종료되지 않은 본인 배정 근무(예정·진행 중)를 다시 확인한다. 남아 있으면 현재 예정 근무 안내를 표시하고 처리하지 않는다. 없으면 확인 후 소속을 해제한다. 나가기는 계정을 유지하고 탈퇴는 계정을 종료한다. 마지막 매니저의 특수 처리는 후속 범위로 남긴다. 탈퇴 후 일반 서비스 회원정보의 추가 보존기간은 0일이다. 계정 접근·세션을 즉시 종료하고 이름·이메일·소셜 식별자·인증 토큰·회원/소속 연결 및 본인 수신 알림은 지체 없이 파기한다. 근무·요청·처리 기록에도 이름과 개인 연결 ID를 남기지 않는다. 다른 구성원 기록의 표시가 필요한 경우에만 “탈퇴한 구성원”으로 표시하고, 다른 정보와 결합하여 재식별 가능하면 해당 개인 관련 상세·기록을 삭제한다. 이름만 바꾼 자료를 익명정보로 간주하지 않는다. 개인정보취급자 등 운영자의 개인정보처리시스템 접속기록은 안전성 확보조치 기준 제8조의 법정 보안기록으로 구분해 1년 이상 별도 보관하며 일반 앱 요청·알림 전체를 그 기록으로 취급하지 않는다. 그 밖에 적용되는 법정 보존 의무가 확인된 항목은 근거·기간을 명시해 분리 보관한다. 캐시·백업에서도 파기하고 복원 시 재유입을 막는다. |
| 매장 나가기 | 계정은 유지하고 소속만 해제한다. 이전 매장 근무표·요청·구성원 접근을 차단한다. 재참여는 유효 코드로 새 소속을 만들며 과거 소속 자동 복구는 없다. |
| 진행 중 요청 | 소속 해제와 요청 정리는 함께 확정한다. 떠나는 사람이 요청자면 진행 요청을 CANCELLED(REQUESTER\_LEFT), 승인 대기 후보면 WITHDRAWN(CANDIDATE\_LEFT)으로 종료한다. 미수락 지정 대상이면 그 대상만 응답 불가로 바꾸고 나머지는 유지한다. 후보 없이 응답 가능한 대상이 0명이 되면 CANCELLED(NO\_ACTIVE\_TARGET)로 종료한다. 종료 요청은 다시 열지 않는다. 승인·수락과 동시에 발생하면 먼저 확정된 최신 상태를 검증하여 한 번만 처리한다. |
| 남은 구성원의 기록 | 매장 나가기는 계정 탈퇴와 다르며 기존 요청 기록·근무 기록을 자동 삭제하지 않는다. 계정 탈퇴는 개인 식별 요소를 파기한다. 탈퇴한 계정으로 접근을 허용하지 않는다. |
| 개인정보 보존 | 탈퇴 후 일반 서비스 회원정보의 추가 보존기간은 0일이다. 계정 접근·세션을 즉시 종료하고 이름·이메일·소셜 식별자·인증 토큰·회원/소속 연결 및 본인 수신 알림은 지체 없이 파기한다. 근무·요청·처리 기록에도 이름과 개인 연결 ID를 남기지 않는다. 다른 구성원 기록의 표시가 필요한 경우에만 “탈퇴한 구성원”으로 표시하고, 다른 정보와 결합하여 재식별 가능하면 해당 개인 관련 상세·기록을 삭제한다. 이름만 바꾼 자료를 익명정보로 간주하지 않는다. 개인정보취급자 등 운영자의 개인정보처리시스템 접속기록은 안전성 확보조치 기준 제8조의 법정 보안기록으로 구분해 1년 이상 별도 보관하며 일반 앱 요청·알림 전체를 그 기록으로 취급하지 않는다. 그 밖에 적용되는 법정 보존 의무가 확인된 항목은 근거·기간을 명시해 분리 보관한다. 캐시·백업에서도 파기하고 복원 시 재유입을 막는다. |

| 약관 | 문서 본문·개인정보 처리방침은 작성 예정이다. 이 정책서로 동의 문서를 대체하지 않는다. 필수 미동의는 가입 차단, 선택 미동의는 가입 가능하다. |

법령 기준과 서비스 선택을 구분한다. 개인정보가 불필요해지면 지체 없이 파기하고, 다른 법령상 보존 의무가 있으면 분리 보관한다는 원칙은 개인정보 보호법 제21조를 따른다. 추가 보존기간 0일 및 탈퇴 이름 표시·연결 정보 삭제 방식은 BATON의 이번 서비스 선택이다. [법제처 생활법령정보: 개인정보 파기의무](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=1&cciNo=1&cnpClsNo=3&csmSeq=1702). 실제 법적 보존 예외가 확인되면 해당 항목만 별도로 반영한다.

법정 보안 접속기록은 일반 서비스 기록과 구분한다. [개인정보의 안전성 확보조치 기준 제8조](https://law.go.kr/admRulLsInfoP.do?admRulSeq=2100000281400)에 따른 개인정보처리시스템 접속기록은 별도 보관·점검 대상으로 관리한다. 위 회원정보 파기 규칙을 근거로 법정 보안기록까지 일괄 삭제하지 않는다.
