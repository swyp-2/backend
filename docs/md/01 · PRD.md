# BATON PRD

기준일  · v5.0

매니저의 근무표 편성과 크루원의 대타 요청·응답, 매니저 수동 최종 승인을 연결하는 MVP다. 기능명세서 v3.2·정책서 v2.0을 현재 개발 기준으로 사용한다.

## 1. 문제와 제품 목표

근무표를 확인하는 곳과 대타를 부탁하고 확정하는 곳이 나뉘면, 누가 실제로 출근해야 하는지 다르게 이해할 수 있다. BATON은 같은 근무를 기준으로 요청·첫 수락 후보·최종 승인·담당자 변경을 연결한다. 수락과 최종 확정을 구분해 미확정 대타를 확정 근무로 오인하지 않게 한다.

| 사용자 | 하고 싶은 일 | 제품이 제공하는 결과 |
| --- | --- | --- |
| 매니저 | 한 번에 근무를 배정하고 변경을 관리 | 복수 근무자·공통 반복 패턴 등록, 공유 근무표, 대타 최종 승인·거절 |
| 크루원 | 내 근무와 동료 일정을 확인하고 대타 부탁 | 본인 시작 전 근무에서 지정 동료 선택, 받은 요청 수락·거절, 진행 상태·알림 확인 |

### 대표 사용자 목적

| 역할 | 유저스토리 |
| --- | --- |
| 매니저 | 매니저는 직원들에게 일정을 공유하기 위해 여러 구성원의 근무를 한 번에 등록할 수 있다. |
| 크루원 | 크루원은 출근하기 어려운 근무를 대신할 사람을 찾기 위해 같은 매장 동료에게 대타를 요청할 수 있다. |
| 매니저 | 매니저는 실제 출근자를 확정하기 위해 동료가 수락한 대타 요청을 최종 승인할 수 있다. |

## 2. 핵심 사용자 흐름

1. 매니저: Google/Apple 로그인 → 약관 → 이름 → 매니저 선택 → 매장 생성 → 공통 코드 전달 → 근무 등록.
2. 크루원: Google/Apple 로그인 → 약관 → 이름 → 크루원 선택 → 초대 코드 참여 → 내/전체 근무 확인.
3. 편성: 근무 추가에서 근무자·일시 입력 → 필요하면 반복 설정 → 미리보기 → 최종 등록. 입력·미리보기 단계에서는 저장하지 않는다.
4. 요청: 크루원이 본인 미래 근무 선택 → 동료 지정 → 요청 보내기. 지정 대상의 받은 요청과 앱 내부 알림에 반영한다.
5. 확정: 지정 동료 첫 수락 → 매니저 승인 대기 → 매니저 최종 승인 확인 → 해당 한 근무의 담당자 변경.
6. 중단: 거절·취소·철회·만료·근무 삭제·소속 해제를 상태별로 처리한다. 승인 전에는 원래 담당자가 유지된다.

## 3. 역할별 권한

| 행동 | 매니저 | 크루원 |
| --- | --- | --- |
| 근무표·소속 구성원 조회 | 가능 | 가능 |
| 근무 추가·반복 등록·단건 삭제 | 가능 | 불가 |
| 근무 수정 | 이번 범위 제외 | 불가 |
| 근무 배정 대상 | 포함 가능 | 포함 가능 |
| 본인 근무 대타 요청·수락 후보 참여 | 불가 | 관계 조건 충족 시 가능 |
| 대타 최종 승인·거절 | 소속 매니저만 | 불가 |
| 초대 코드 확인·복사 | 가능 | 불가 |
| 본인 앱 내부 알림 | 가능 | 가능 |
| 개인 요청 목록·진행 기록 | 매니저 승인 상세에서 처리 | 보낸·받은 요청과 상세에서 확인 |
| 근무 변경 이력 메뉴 | 제외 | 제외 |

## 4. 이번 MVP의 제공 범위

| 영역 | 제공 기능 | 현재 기준 |
| --- | --- | --- |
| 가입·매장 | Google·Apple, 약관·이름·역할, 매장 생성·공통 코드 참여 | 이름 2\~15자, 매장명 1\~15자, 코드 대문자·숫자 8자리. 참여 승인 없음. |
| 근무표 | 내/전체 달력, 월 내 근무 목록, 날짜별 전원 명단 | 인원 중복 제거. 이름·개인 색·시간. 내/전체 탭 스와이프 포함. |
| 편성 | 복수 근무자·공통 패턴·최종 확인·단건 삭제 | 0분 초과·24시간 미만. 달력상 최대 1개월 반복. 근무 수정 없음. |
| 대타 | 지정 요청·첫 수락·즉시 거절·취소·철회·종료 | 크루원만 참여. 한 근무의 활성 요청 한 건. 동시 수락 후보 한 명. |
| 최종 승인 | 담당자 변경·거절 | 최종 확인 유지. 거절 사유 입력 없음. |
| 알림 | 생성·단일 목록·진입 읽음·표시점·관련 상세 | 7일 보관. 최신순 20개씩. 결과는 요청자·후보·매니저. 만료·근무 삭제 별도 알림 없음. |
| 프로필·계정 | 본인·구성원·설정·로그아웃·나가기·탈퇴 | 예정/진행 근무가 남으면 정리 안내. 탈퇴 개인 식별 요소 파기·법정 보안기록 구분. |

## 5. 제외 범위

- 근무 수정, 양쪽 근무 변경 이력 화면, 매니저의 대타 요청·후보 참여.
- 대타 외부 링크·카카오/OS 공유·푸시 발송·급여 계산·다점포 확장·직원별 다른 반복 패턴의 한 번 제출.
- 로그인 없는 체험·예시 계정 전환·코드 없이 참여·초대 코드 재발급 UI.
- AP-01 처리 대기 목록·알림 필터 탭·거절 사유 입력·크루원 거절 확인 팝업·사용자 알림 삭제·전체 읽음 버튼.

## 6. 주요 예외·복구

| 상황 | 기대 동작 |
| --- | --- |
| 가입 도중 종료·소속 없는 기존 계정 | 저장한 가입 단계 다음으로 복귀. 역할에 따라 ST-01/ST-03, 역할 미선택은 CO-05. |
| 두 동료가 동시에 수락 | 서버에서 한 후보만 확정. 나머지는 최신 승인 대기 상태를 확인. |
| 승인·취소·탈퇴가 동시에 발생 | 최신 상태와 소속을 재확인하고 한 처리만 확정. 부분 반영 방지. |
| 알림 진입 뒤 새 알림 도착 | 기존 알림은 읽음, 진입 이후 알림은 미읽음. 읽음은 요청 처리 아님. |
| 알림 7일 만료 후 미처리 승인 존재 | 알림만 만료. 매니저 SH-02에서 AP-02로 진입해 승인 가능. |
| 저장·조회 실패 | 입력 유지·재시도. 실패를 빈 목록이나 완료로 표시하지 않음. |

## 7. 완료 판단·사용성 확인

다음은 검수할 기준이며 아직 달성한 성과가 아니다. 활성 사용자 수·응답 시간 등 정량 목표는 확정하지 않았으므로 임의 수치를 두지 않는다.

- 매니저가 근무를 등록하면 같은 매장 크루원의 독립 세션에서 볼 수 있다.
- 크루원이 요청·수락해도 승인 전까지 담당자가 유지된다.
- 매니저 승인 후 관련 사용자 모두 같은 최종 담당자를 확인한다.
- 다른 매장·비대상·탈퇴자가 요청·근무를 조회하거나 변경하지 못한다.
- 현재 기능·정책에 대응하는 QA를 실제 서버 연동 환경에서 실행하고 증거를 남긴다.
