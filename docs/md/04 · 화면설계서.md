# BATON 화면설계서

기준일  · v5.0

현재 Figma 화면과 PM 후속 결정을 설명하는 개발용 문서다. 24개 화면 ID를 유지하며 역할·상태 예시는 별도 화면 번호로 늘리지 않는다. 기능명세서 v3.2·정책서 v2.0에 맞춰 삭제 기능과 최신 알림 기준을 반영했다.

## 1. 기준 파일과 읽는 방법

[현재 Figma 화면설계 파일](https://www.figma.com/design/XlvisVZqlpKrajT2fiL0lU/Untitled?node-id=0-1)

제출된 넘길거.fig와 이후 PM의 크루원 거절 확인 삭제·정책 확정을 함께 반영했다. 실제 Figma 프레임의 실시간 수정·완료 상태는 이 문서로 검증한 것이 아니다. 아래 동작 명세와 디자이너의 최종 시안을 함께 사용한다.

## 2. 화면 ID와 기능 ID

| 종류 | 예시 | 의미 |
| --- | --- | --- |
| 화면 ID | CA-01 · 내 근무 | 사용자가 보는 화면. Figma 프레임 제목과 개발 화면을 찾는 번호. |
| 기능 ID | SCH-01 · 근무표 조회 | 그 화면에서 수행하는 동작. 한 화면에 여러 기능이 연결될 수 있음. |
| 상태·역할 | RQ-03 받은 요청 / 보낸 요청 | 같은 화면 ID의 사용자 관계별 모습. 확인 팝업·종료 결과를 전부 새 화면으로 해석하지 않음. |

| 화면 코드 | 뜻 |
| --- | --- |
| CO | 공통 진입·가입 |
| ST | 매장 |
| CA | 달력·근무표 |
| SH | 근무 상세 |
| ED | 근무 등록·설정 |
| RQ | 대타 요청 |
| AP | 최종 승인 |
| NT | 알림 |
| PR | 프로필·계정 |

## 5. 화면별 상세

### CO-01 · 로그인

| 항목 | 내용 |
| --- | --- |
| Screen Title / 역할 | login / 공통 |
| 진입 | 앱 실행 |
| 동작·이동 | Google·Apple 인증 성공 후 서버의 가입 상태·소속을 조회한다. 신규는 CO-02, 가입 완료·소속 보유 회원은 근무표, 소속이 없으면 저장된 단계의 ST-01/ST-03 또는 CO-05로 이동한다. |
| 권한·예외 | 실패·취소는 현재 화면에서 재시도. 체험 우회 없음. |

## 6. 요청 상세의 상태·관계별 행동

| 상태 | 관계·사건 | 행동 | 결과 |
| --- | --- | --- | --- |
| WAITING | 미응답 지정 크루원 | 수락 / 거절 | 첫 수락은 승인 대기. 거절은 확인 팝업 없이 즉시 처리. 전원 거절은 ALL\_DECLINED. |
| WAITING | 이미 거절한 지정 크루원 | 수락 | 진행 중일 때만 재수락 가능. 종료 뒤 재개 없음. |
| WAITING / PENDING\_MANAGER | 요청 크루원 | 요청 취소 | CANCELLED. 원래 담당자 유지. |
| PENDING\_MANAGER | 현재 후보 크루원 | 수락 철회 | WITHDRAWN. 자동 재모집 없음. |
| PENDING\_MANAGER | 소속 매니저 | 최종 승인 / 거절 | APPROVED 때만 담당자 변경. 거절은 REJECTED. |
| PENDING\_MANAGER | 후보 아닌 지정 크루원 | 상태 조회 | 수락·거절·철회 버튼 없음. |
| 종료 | 접근 가능한 관계자 | 결과·진행 기록 조회 | 처리 버튼 없음. |
| 진행 중 | 시작 시각 도달 | 자동 만료 | EXPIRED. 수락·승인 불가. |
| 진행 중 | 근무 삭제 | 요청 종료 | 기존 SOURCE\_CHANGED에 삭제 사유를 연결. 근무 수정 시나리오는 제외. |
| 진행 중 | 요청자 소속 해제 | 요청 취소 | CANCELLED / REQUESTER\_LEFT. 원래 담당자 유지. |
| PENDING\_MANAGER | 후보 소속 해제 | 수락 철회 | WITHDRAWN / CANDIDATE\_LEFT. 자동 재모집 없음. |
| WAITING | 지정 대상 소속 해제 | 해당 대상만 응답 불가 | 나머지는 유지. 응답 가능한 대상 0명이면 CANCELLED / NO\_ACTIVE\_TARGET. |

## 7. 공통 상태·반응형 기준

- 초기 조회·로딩·데이터 0건·조회 실패·저장 중·저장 실패를 구분한다. 실패를 빈 목록이나 완료로 표시하지 않는다.
- 긴 이름·복수 선택 수·많은 근무·야간 날짜를 실제 값으로 표시한다. 수치와 버튼 문구를 시안에 하드코딩하지 않는다.
- 대표 화면 옆에 빈 상태·오류·비활성 예시를 둔다. 각 상태마다 별도 전체 디자인을 요구하지 않는다.
- 본문 스크롤·하단 버튼·기기 안전 영역을 구분한다. 시안의 아래로 긴 내용은 실제 구현에서 접근할 수 있어야 한다.
- 다른 매장·비대상·소속 해제 사용자의 화면 접근과 행동은 서버에서도 차단한다.

## 8. 디자이너 선행 전달 묶음
